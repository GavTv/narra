# Narra — коротко, чтобы объяснить

## Структура `src` (FSD)

**Почему FSD:** обычный путь — всё в `components/` и `utils/`, через месяц непонятно, где чат, где парсер, где типы.  
FSD режет по смыслу: экран (`app`) → блоки UI (`widgets`) → действия (`features`) → данные (`entities`) → общее (`shared`) → сервер (`server`).  
Плюс: правка чата не ломает загрузку файла; на защите ясно «где мозг, где картинка».

### app — точка входа Next: страница приложения и тонкие API-роуты
- **a) api** — два POST: `/analyze` (дашборд), `/chat` (ответ); JSON → server → ответ/ошибка

### entities — доменные сущности приложения: «что есть» (отчёт, анализ, чат) — типы и ядро логики данных, без UI и без кнопок/хуков сценариев
- **a) analysis** — дашборд (метрики, графики)  
- **b) chat** — диалог (сообщения, источники)  
- **c) report** — отчёт + счёт/поиск по таблице (+ тесты в `lib`)

### features — сценарии пользователя: «что делает» (загрузить, проанализировать, спросить), хуки/UI сценария без доменного ядра
- **a) analyzeReport** — сессия анализа  
- **b) askReport** — отправить вопрос в чат  
- **c) parseUpload** — файл/текст → таблица

### server — серверная сторона: ИИ, пайплайн анализа/чата, RAG; вызывается из `app/api`
- **a) ai** — вызов модели (GigaChat)  
- **b) analyzeReport / askReport** — оркестрация анализа и чата  
- **c) rag** — фрагменты отчёта под вопрос

### shared — общее для всех слоёв: константы, утилиты, базовые типы (без бизнес-логики отчёта)
- **a) consts** — лимиты, тексты  
- **b) lib** — format, http, validation  
- **c) types** — общие типы

### widgets — крупные блоки UI на экране: собирают features/entities в готовые панели
- **a) Header / UploadPanel** — шапка и загрузка  
- **b) Dashboard** — метрики и графики  
- **c) ReportChat** — окно чата

### test — папка только для тестов, не для продакшена
Зачем отдельно: чтобы не смешивать боевой код с учебными таблицами.  
Здесь лежат готовые маленькие отчёты (продажи, авто и т.п.). Юнит-тесты в `report/lib` и RAG берут их отсюда и проверяют: «сколько», «какой пик», индекс, поиск — без ручного Excel каждый раз.  
В приложение пользователю эти файлы не отдаются.
- `fixtures.ts` — сами мини-отчёты для тестов
