# БЛОК 1. Сайт

## Старт

(Открыть live.)

Сейчас я покажу Narra — сервис, который из сырых данных собирает историю, графики и чат. Без учета регистрации: то есть у тебя есть файл, который
 можно вставить в данное приложение(сайт) для получения грамотной структуры данныйх. 

 Загруженный файл, не уходит в постоянное хранилище, поэтому данные можно спокойно менять,
без опасения о перегрузке. 



Внизу три шага: загрузили → получили историю → задали вопрос.

Справа основная форма. Два режима — файл или текст. (кнопка выше)

(Переключить табы «Файл» ↔ «Текст».)

Сейчас переключу, чтобы было видно, как меняется интерфейс.

---

## Режим «Файл»

В режиме файла — большая зона: перетащил CSV или Excel, либо кликнул и выбрал. Лимит пять мегабайт. Если файл не подходит, покажем ошибку здесь же, без белого экрана.

Для демо быстрее всего нажму «Демо-отчёт» — подставится готовый пример, и сразу запустится анализ.

(Нажать «Демо-отчёт».)

---

## Режим «Текст» (по желанию, коротко)

(Если ещё не ушёл в анализ — переключить на «Текст».)

Есть и режим текста: вставил сырой отчёт словами, нажал «Создать дашборд» — дальше тот же путь, что и с файлом. Если текста слишком мало, сервис попросит добавить.

(Вернуться на «Файл» и нажать «Демо-отчёт», если ещё не запускал анализ.)

---

## Загрузка

Пока идёт анализ, пользователь видит прогресс и стадии:
- читаем структуру;
- ищем связи;
- подбираем графики;
- собираем историю.

Не пустой экран, а понятное ожидание. В шапке уже «Контекст загружен».

---

## Дашборд

Готово — открылся дашборд. Это главный экран результата.

Сверху видно, какой файл сейчас в работе, тип источника и объём — строки и колонки. «Другой отчёт» сбрасывает сессию и возвращает на старт. Сейчас остаёмся здесь.

(Опционально: F5 — дашборд остаётся во вкладке.)

Слева главный нарратив: короткий заголовок и 2–3 предложения сути из данных — пик, доля, что выделяется. Не шаблон «сводка по полям», а читаемая история отчёта.

(Зачитать вслух заголовок и summary с экрана.)

Справа быстрые метрики: название, значение и короткая расшифровка — цифры «на пальцах» ещё до графиков.

Ниже графики. Тип — столбцы, линия или круговая — под характер данных. Навожу — есть подсказка с числом. На линии по датам каждый день один раз, без повторов на оси.

(Навести курсор на график.)

---

## Чат

Внизу чат. Слева готовые вопросы — нажму один. Справа диалог: вопрос уходит, бот ищет только в отчёте. Под ответом могут быть чипы источника.

### Вопрос 1 — по данным

(Нажать suggested-вопрос или спросить про сумму / день / максимум с метрик.)

Вот ответ уже по этим данным — не общая болтовня модели.

### Вопрос 2 — прибыльный месяц

(Спросить: «Какой самый прибыльный месяц?» или «Какой самый неприбыльный месяц?».)

Можно спросить и про структуру отчёта или прибыльный месяц — сервис считает по загруженной таблице.

### Вопрос 3 — мимо данных

(Спросить: «Какой курс доллара?».)

А теперь вопрос мимо отчёта — например, про курс доллара. Смотрите: сервис не выдумывает и честно говорит, что таких данных в отчёте нет. Это ключевой момент.

# БЛОК 2. Код — что за что отвечает

Открой GitHub или IDE, дерево `src/`.  
Теперь объясняешь устройство, уже опираясь на то, что зритель видел на сайте.

## 2.0. Общий принцип

```text
Сайт (кнопки/экраны)
  ↓
features (клиентские действия: parse, fetch, hooks)
  ↓
app/api (тонкие Next routes)
  ↓
server (AI-анализ и RAG-чат)
  ↓
entities (чистые типы и доменная логика)
```

Импорты вниз по FSD. `server` в браузер не попадает.

---

## 2.1. `app/` — Next.js: страница и API

| Файл | Связь с UI | Ответственность |
|------|------------|-----------------|
| `app/page.tsx` | Все экраны 1–3 | Решает: показать лендинг / loading / dashboard. Берёт состояние из `useAnalyzeSession` (ждёт restore из `sessionStorage`) |
| `app/layout.tsx` | Общая оболочка | Layout, стили, metadata |
| `app/api/analyze/route.ts` | После upload/демо | Принимает POST, отдаёт JSON анализа. Сам почти ничего не считает |
| `app/api/chat/route.ts` | Кнопка отправки в чате | Принимает вопрос + source + history, отдаёт answer + citations |

**Что сказать:**  
«Кнопки на сайте в итоге бьют в эти два API. Routes тонкие — оркестрация ниже.»

---

## 2.2. `widgets/` — то, что пользователь буквально видит

| Виджет | Кусок UI из блока 1 |
|--------|---------------------|
| `Header` | Шапка, бейджи «Готов к анализу» / «Контекст загружен» |
| `UploadPanel` | Карточка «Загрузите отчёт», табы Файл/Текст, dropzone, «Демо-отчёт», «Создать дашборд» |
| `Dashboard` | Экран результата: имя файла, «Другой отчёт», hero, метрики, сетка графиков |
| `Dashboard/ChartCard` | Одна карточка графика + tooltip (компактно, без длинного footer) |
| `ReportChat` | Весь блок Ask the Data: suggested, лента, поле ввода, citations |

Виджеты рисуют UI и вызывают features, но **не содержат** промпты и вызовы LLM.

---

## 2.3. `features/` — действия за кнопками

### `parseUpload` — за кнопками файла/текста
- Читает CSV/XLSX/текст в браузере
- Режет лимиты (размер, строки, колонки)
- Собирает единый объект данных для дальнейшей отправки
- Ошибки парсинга → красный текст в UploadPanel

### `analyzeReport` — за переходом на loading/dashboard
- `useAnalyzeSession` — статусы idle/loading/ready/error + восстановление сессии из `sessionStorage`
- `api/analyzeReport` — `fetch /api/analyze`
- `LoadingDashboard` — экран 2 со стадиями и прогрессом

### `askReport` — за чатом
- `useReportChat` — сообщения, «думает», история; тоже в `sessionStorage` по ключу источника
- `api/askReport` — `fetch /api/chat`

**Что сказать:**  
«Каждая заметная кнопка на сайте привязана к feature: распарсить, проанализировать, спросить. Сессия и чат переживают refresh во вкладке.»

---

## 2.4. `entities/` — модель данных и «мозги без нейросети»

| Entity | Зачем |
|--------|-------|
| `report` | Форма отчёта, демо-данные, индекс чанков, retrieve, локальный анализ, **queryEngine** (суммы / пики / месяцы), **reportOverview** (короткий title) |
| `analysis` | Типы того, что рисует dashboard: summary, metrics, charts |
| `chat` | Типы сообщений, ответа, citations |

Сюда же fallback: если AI недоступен, dashboard и простые ответы всё равно собираются из `report` local-логики.  
Заголовок дашборда всегда нормализуется через `withReportOverview` — AI не может подставить длинный «пик выручки…» вместо «Отчёт за … по …».

---

## 2.5. `shared/` — общая инфраструктура

- `validation` — Zod-схемы тела запросов (что API принимает)
- `http` / `result` — аккуратный fetch и единый формат ok/error на сервере
- `sessionStorage` — persist сессии анализа и истории чата во вкладке
- `format`, `cn`, `limits`, `types` — мелочи для UI и парсинга (в т.ч. merge точек графика по дате)

---

## 2.6. `server/` — то, чего нет на кнопках, но есть после клика

### `server/analyzeReport`
Use-case кнопки «проанализируй»:  
валидация → LLM (narrative + metrics + charts) → если не вышло, local fallback → **`withReportOverview`** → DTO на фронт.

### `server/ai`
Промпты и вызов моделей для дашборда (+ хелперы для чата).  
- `generateAnalysis` — Gemini (+ cooldown при 429)  
- `providers` — запасные **OpenRouter / OpenAI / Groq** (`AI_PROVIDER` поднимает выбранный вверх)  
Именно здесь модель **выбирает типы графиков** и пишет **нарратив 2–3 предложения**; `withReportOverview` сохраняет AI-summary, если он содержательный, иначе подставляет локальный narrative из цифр.

### `server/askReport`
Use-case отправки вопроса в чате:  
валидация → индекс отчёта → RAG-граф → fallback.

### `server/rag` (`ragGraph.ts`)
Ответ на «как чат не врёт»:
1. Если вопрос расчётный («сколько всего», «прибыльный месяц») — считает локально (`queryEngine`), без модели  
2. Иначе достаёт релевантные куски отчёта (при пустом lexical — схема + срез строк)  
3. Модель отвечает **только по этим кускам** (Gemini → alt LLM при квоте)  
4. Проверяет citations  
5. Если факта нет — честный отказ (как в вопросе про курс доллара)

## 2.7. Связка «кнопка → код» (удобно ткнуть курсором)

| На сайте нажали / увидели | Где в коде |
|---------------------------|------------|
| Таб «Файл» / dropzone | `widgets/UploadPanel` + `features/parseUpload` |
| «Демо-отчёт» | `UploadPanel` → `sampleData` + `useAnalyzeSession.analyze` |
| «Создать дашборд» (текст) | `parseUpload/textToSource` → analyze |
| Экран стадий анализа | `features/analyzeReport/ui/LoadingDashboard` |
| Hero + метрики + графики | `widgets/Dashboard` + `ChartCard`; данные из `/api/analyze` + `withReportOverview` |
| Refresh — дашборд на месте | `shared/lib/sessionStorage` + `useAnalyzeSession` / `useReportChat` |
| «Другой отчёт» | `useAnalyzeSession.reset` → clear session/chat → лендинг |
| Suggested-вопрос / Send в чате | `widgets/ReportChat` + `features/askReport` → `/api/chat` → `server/rag` |
| «Прибыльный месяц» | `entities/report/lib/queryEngine` (до LLM) |
| Чипы «Источник» | `citations` из RAG-ответа |
