## Экран 1. Лендинг (стартовая страница)

Открой live. На экране две зоны: слева текст, справа форма.

**Скажи:**  
«Сейчас я покажу Narra — сервис, который из сырых данных собирает историю, графики и чат. Без регистрации: открыл ссылку — и можно пользоваться. Слева рассказ о продукте, справа — зона загрузки.»

### Шапка (Header)
- Слева логотип **narra**
- Справа бейдж **«Готов к анализу»**
- Текст **«Данные не сохраняются»** — обещание пользователю: файл не уходит в хранилище навсегда

**Скажи:**  
«В шапке сразу видно бренд и важное обещание — данные не сохраняются. Статус сейчас: готов к анализу.»

### Левая колонка — оффер
- Плашка **AI data storyteller**
- Большой заголовок: «Данные уже знают ответ»
- Подзаголовок: что сервис делает (загрузил → история → графики → вопросы)
- Три пункта-галочки:
  - CSV, Excel и текст
  - Без регистрации
  - Ответы только по данным
- Внизу шаги 01 / 02 / 03: Загрузите → Получите историю → Задайте вопрос

**Скажи:**  
«Слева короткий оффер: поддерживаем таблицы и текст, без логина, и ответы только по загруженным данным. Внизу три шага пути пользователя.»

### Правая колонка — карточка «Загрузите отчёт»
Это главная рабочая зона на старте.

#### Переключатель режима
Две кнопки-таба:
- **«Файл»** — загрузка CSV/XLSX
- **«Текст»** — вставка сырого отчёта текстом

**На Loom:** переключи туда-сюда, покажи что UI меняется.

**Скажи:**  
«Справа основная форма. Два режима — файл или текст. Сейчас переключу, чтобы было видно, как меняется интерфейс.»

## Экран 1а. Режим «Файл»

### Большая зона dropzone
- Текст: «Перетащите CSV или Excel сюда»
- Подпись: «или нажмите, чтобы выбрать файл · до 5 МБ»
- Клик по зоне → системный выбор файла
- Drag-and-drop тоже работает

**Что происходит после выбора файла:**
1. В зоне появляется состояние «Читаем [имя файла]» (спиннер)
2. Если файл ок → сразу уходим на загрузку анализа (экран 2)
3. Если файл плохой (не CSV/XLSX, слишком большой, пустой, без строк) → **красная ошибка под формой**, остаёмся на лендинге

**Скажи:**  
«В режиме файла — большая зона: перетащил CSV или Excel, либо кликнул и выбрал. Лимит пять мегабайт. Если файл не подходит, покажем ошибку здесь же, без белого экрана.»

### Кнопка «Демо-отчёт» (внизу карточки)
- Текст: «Нет файла? Откройте готовый пример.»
- Кнопка **«Демо-отчёт»**

**Нажимаем «Демо-отчёт» →** подставляется готовый пример данных и сразу запускается анализ (без своего файла).  
Это лучший путь для записи Loom.

**Скажи:**  
«Для демо быстрее всего нажму „Демо-отчёт“ — подставится готовый пример, и сразу запустится анализ.»

### Под карточкой
Мелкий текст: «Файл используется только для текущего анализа».

### Если анализ уже падал раньше
Над/под формой может быть баннер **«Анализ не завершён»** + текст ошибки.  
Тогда пользователь может загрузить файл заново.

## Экран 1б. Режим «Текст»

Переключи таб на **«Текст»**.

### Что на экране
- Большое поле textarea с плейсхолдером-примером
- Счётчик знаков справа внизу
- Кнопка **«Создать дашборд»** (тёмная, со звёздочкой)

**Как пользоваться:**
1. Вставляем сырой текст отчёта (хотя бы пару предложений)
2. Жмём **«Создать дашборд»**
3. Если текста мало → ошибка «Добавьте чуть больше данных…»
4. Если ок → тот же переход на экран загрузки анализа

**Скажи:**  
«Есть и режим текста: вставил сырой отчёт словами, нажал „Создать дашборд“ — дальше тот же путь, что и с файлом. Если текста слишком мало, сервис попросит добавить.»

*(На записи после показа текста можно вернуться и жать «Демо-отчёт».)*

## Экран 2. Загрузка анализа (Loading)

Появляется после успешного старта анализа.

### Шапка меняется
- Бейдж теперь **«Контекст загружен»**
- «Данные не сохраняются» в compact-режиме может скрываться

### Контент loading
- Плашка **«AI-анализ»** + имя источника
- Крупный текст текущего этапа, по очереди:
  1. Читаем структуру данных  
  2. Ищем связи и аномалии  
  3. Подбираем визуализации  
  4. Собираем историю  
- Прогресс-бар (растёт, пока ждём ответ)
- Ниже скелетоны «будущих» карточек метрик/графиков — чтобы не было пустого белого экрана

**Скажи:**  
«Пока идёт анализ, пользователь видит прогресс и стадии — читаем структуру, ищем связи, подбираем графики, собираем историю. Не пустой экран, а понятное ожидание. В шапке уже „Контекст загружен“.»

## Экран 3. Дашборд результата

После успешного анализа. Это главный экран продукта.

**Скажи:**  
«Готово — открылся дашборд. Это главный экран результата.»

### 3.1. Верхняя полоска источника
- Иконка файла
- **Имя отчёта** (имя файла / «Демо» / «Вставленный отчёт»)
- Бейдж типа: CSV / Excel / Текст / Демо
- Строка статистики: сколько **строк** и **колонок**
- Кнопка **«Другой отчёт»** (со стрелкой сброса)

**Нажимаем «Другой отчёт» →** возврат на лендинг, сессия очищается, можно загрузить новый файл.

**Скажи:**  
«Сверху видно, какой файл сейчас в работе, тип источника и объём — строки и колонки. „Другой отчёт“ сбрасывает сессию и возвращает на старт. Сейчас остаёмся здесь.»

### 3.2. Hero — главный нарратив (левый большой тёмный блок)
Это «история по данным», не таблица.

На блоке видно:
- маленький eyebrow-тег сверху (короткая тема отчёта)
- метка **«Только факты отчёта»**
- **крупный заголовок-инсайт**
- **2–3 предложения summary** — суть выгрузки человеческим языком
- стрелка/акцент, что дальше можно копать глубже

**Скажи:**  
«Слева главный нарратив — не таблица, а история: короткий тег, заголовок-инсайт и два-три предложения сути. Обещание блока — опираемся только на факты отчёта.»  
*(Зачитай вслух 1–2 фразы из summary на экране.)*

### 3.3. Метрики (правая колонка / рядом с hero)
Несколько карточек с:
- названием метрики
- крупным значением
- короткой подписью-деталью
- цветовым тоном (рост / предупреждение / нейтрально) и стрелкой

**Скажи:**  
«Справа быстрые метрики: название, значение и короткая расшифровка — цифры „на пальцах“ ещё до графиков.»

### 3.4. Графики (ниже, сетка 2–3 карточки)
Каждая карточка графика содержит:
- тип визуализации (столбцы / линия / круговая) — **модель сама выбирает подходящий**
- заголовок и подзаголовок
- сам интерактивный график (можно навести — tooltip с числом)
- короткий **insight** под графиком — что на нём важно увидеть

**Скажи:**  
«Ниже два-три графика. Тип — столбцы, линия или круговая — сервис сам подбирает под характер данных. Навожу — есть подсказка с числом. Под каждым короткий комментарий, на что смотреть.»

### 3.5. Блок чата «Спросите данные напрямую» (внизу страницы)

Большая секция из двух частей.

#### Левая колонка чата
- Заголовок **«Спросите данные напрямую»**
- Пояснение: ответ ограничен текущим отчётом; если факта нет — скажет честно
- Список кнопок **«Можно спросить»** — готовые вопросы (suggested)

**Нажимаем любую suggested-кнопку →** вопрос сразу уходит в чат как будто мы его набрали.

#### Правая колонка чата — диалог
- Шапка: **Narra AI**, имя текущего файла/контекста, бейдж **«Только отчёт»**
- Лента сообщений:
  - первое сообщение бота — welcome («вижу N строк…» / «отчёт прочитан…»)
  - наши вопросы справа
  - ответы слева
- Под ответом бота могут быть чипы **«Источник»** — откуда в отчёте взяли факт
- Пока думает — строка **«Ищу только в отчёте»** со спиннером

#### Поле ввода внизу
- Плейсхолдер: «Спросите что-нибудь про эти данные»
- Кнопка отправки (стрелка вверх)
- Enter / клик по кнопке отправляет вопрос

**Скажи:**  
«Внизу чат. Слева готовые вопросы — нажму один. Справа диалог: вопрос уходит, бот ищет только в отчёте. Под ответом могут быть чипы источника.»

### Что показать в чате на Loom (обязательный мини-сценарий)

**Вопрос 1 — по данным** (из suggested или свой):  
например про сумму / день / максимум из того, что видно на метриках.  
→ Получаем ответ по отчёту, желательно с чипами источника.

**Скажи после ответа:**  
«Вот ответ уже по этим данным — не общая болтовня модели.»

**Вопрос 2 — мимо данных:**  
«Какой курс доллара?» / «Кто президент Франции?»  
→ Должен **честно отказать** (нет в отчёте / точных данных нет).  

**Скажи:**  
«А теперь вопрос мимо отчёта — например, про курс доллара. Смотрите: сервис не выдумывает и честно говорит, что таких данных в отчёте нет. Это ключевой момент.»

# БЛОК 2. Код — что за что отвечает

Открой GitHub или IDE, дерево `src/`.  
Теперь объясняешь устройство, уже опираясь на то, что зритель видел на сайте.

## 2.0. Общий принцип

```text
Сайт (кнопки/экраны)
  ↓
features (клиентские действия: parse, fetch, hooks)
  ↓
app/api (тонкие Next routes)
  ↓
server (AI-анализ и RAG-чат)
  ↓
entities (чистые типы и доменная логика)
```

Импорты вниз по FSD. `server` в браузер не попадает.

## 2.1. `app/` — Next.js: страница и API

| Файл | Связь с UI | Ответственность |
|------|------------|-----------------|
| `app/page.tsx` | Все экраны 1–3 | Решает: показать лендинг / loading / dashboard. Берёт состояние из `useAnalyzeSession` |
| `app/layout.tsx` | Общая оболочка | Layout, стили, metadata |
| `app/api/analyze/route.ts` | После upload/демо | Принимает POST, отдаёт JSON анализа. Сам почти ничего не считает |
| `app/api/chat/route.ts` | Кнопка отправки в чате | Принимает вопрос + source + history, отдаёт answer + citations |

**Что сказать:**  
«Кнопки на сайте в итоге бьют в эти два API. Routes тонкие — оркестрация ниже.»

## 2.3. `features/` — действия за кнопками

### `parseUpload` — за кнопками файла/текста
- Читает CSV/XLSX/текст в браузере
- Режет лимиты (размер, строки, колонки)
- Собирает единый объект данных для дальнейшей отправки
- Ошибки парсинга → красный текст в UploadPanel

### `analyzeReport` — за переходом на loading/dashboard
- `useAnalyzeSession` — статусы idle/loading/ready/error (переключение экранов)
- `api/analyzeReport` — `fetch /api/analyze`
- `LoadingDashboard` — экран 2 со стадиями и прогрессом

### `askReport` — за чатом
- `useReportChat` — сообщения, «думает», история последних реплик
- `api/askReport` — `fetch /api/chat`

**Что сказать:**  
«Каждая заметная кнопка на сайте привязана к feature: распарсить, проанализировать, спросить.»

---

## 2.4. `entities/` — модель данных и «мозги без нейросети»

| Entity | Зачем |
|--------|-------|
| `report` | Форма отчёта, демо-данные, индекс чанков, поиск по чанкам, локальный анализ/ответы без Gemini |
| `analysis` | Типы того, что рисует dashboard: summary, metrics, charts |
| `chat` | Типы сообщений, ответа, citations |

Сюда же fallback: если AI недоступен, dashboard и простые ответы всё равно собираются из `report` local-логики.

---

## 2.5. `shared/` — общая инфраструктура

- `validation` — Zod-схемы тела запросов (что API принимает)
- `http` / `result` — аккуратный fetch и единый формат ok/error на сервере
- `format`, `cn`, `limits`, `types` — мелочи для UI и парсинга

---

## 2.6. `server/` — то, чего нет на кнопках, но есть после клика

### `server/analyzeReport`
Use-case кнопки «проанализируй»:  
валидация → Gemini (narrative + metrics + charts) → если не вышло, local fallback → DTO на фронт.

### `server/ai`
Промпты и вызов Gemini для дашборда (+ хелперы для чата).  
Именно здесь модель **выбирает типы графиков** и пишет hero-текст.

### `server/askReport`
Use-case отправки вопроса в чате:  
валидация → индекс отчёта → RAG-граф → fallback.

### `server/rag` (`ragGraph.ts`)
Ответ на «как чат не врёт»:
1. Если вопрос расчётный («сколько всего») — считает локально, без модели  
2. Иначе достаёт релевантные куски отчёта  
3. Модель отвечает **только по этим кускам**  
4. Проверяет citations  
5. Если факта нет — честный отказ (как в вопросе про курс доллара)

## 2.7. Связка «кнопка → код» (удобно ткнуть курсором)

| На сайте нажали / увидели | Где в коде |
|---------------------------|------------|
| Таб «Файл» / dropzone | `widgets/UploadPanel` + `features/parseUpload` |
| «Демо-отчёт» | `UploadPanel` → `sampleData` + `useAnalyzeSession.analyze` |
| «Создать дашборд» (текст) | `parseUpload/textToSource` → analyze |
| Экран стадий анализа | `features/analyzeReport/ui/LoadingDashboard` |
| Hero + метрики + графики | `widgets/Dashboard` + `ChartCard`, данные из `/api/analyze` |
| «Другой отчёт» | `useAnalyzeSession.reset` → снова лендинг |
| Suggested-вопрос / Send в чате | `widgets/ReportChat` + `features/askReport` → `/api/chat` → `server/rag` |
| Чипы «Источник» | `citations` из RAG-ответа |
